# 后端分层结构说明

## 当前目标

本分支基于 `deploy` 的交易稳定性代码继续重构，只整理后端结构，不改前端协议，不改数据库 schema，不改撮合核心逻辑。

## 已完成分层

### Payload Builder

新增：

- `apps/server/src/services/market-payloads.ts`
- `apps/server/src/services/user-payloads.ts`

职责：

- `MarketPayloadBuilder` 负责 `market`、`market:tick`、当前轮次、历史、settlement preview、transport meta。
- `UserPayloadBuilder` 负责 `user` 和 `user:trade` 两种用户负载。

收益：

- `index.ts` 不再直接拼装实时市场 payload。
- `user:trade` 的轻量交易推送被明确保留，避免后续误删。
- 后续前端重构可基于这些 builder 再扩展 layered stream。

### WebSocket Session

新增：

- `apps/server/src/services/market-ws-session.ts`
- `apps/server/src/services/user-ws-session.ts`

职责：

- `MarketWsSession` 负责市场 WS 的发送节流、pending 合并、背压判断、full/tick 定时和关闭清理。
- `UserWsSession` 负责 `user` / `user:trade` 消息构建、发送和用户事件订阅清理。

收益：

- `/ws/market` 和 `/ws/user` 的路由入口只负责鉴权、连接计数、心跳和审计。
- 实时推送调度可以独立测试和继续优化。

### Route Group

新增：

- `apps/server/src/routes/health.ts`
- `apps/server/src/routes/ws.ts`

职责：

- `health.ts` 注册 `/health`、`/api/health/live`、`/api/health/ready`、`/api/metrics`、`/metrics`。
- `ws.ts` 注册 `/ws/market` 和 `/ws/user`。

## 未改变的核心逻辑

- `SimulationEngine` 的交易、平仓、反手、订单 lot、结算逻辑未迁移。
- `AppStore` 的 transaction、订单、持仓、日志持久化语义未修改。
- HTTP 业务接口请求/响应结构保持不变。
- WebSocket 消息类型和负载结构保持不变。

## 后续建议拆分顺序

建议继续按低风险顺序拆分：

1. `auth/me`：登录、me、bootstrap、个人资料。
2. `users`：用户管理和批量创建。
3. `trading`：orders、positions、rounds。
4. `logs/export`：日志检索、导出、数据集导出。
5. `system/matching`：行情源状态、撮合盘口查询。

每拆一组都应保持现有 handler 逻辑不变，只移动注册位置和依赖注入方式。
