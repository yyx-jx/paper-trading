# 测试与生产服务切换手册

本文档只说明一件事：如何在远程服务器上切换 `green` 测试环境与 `production` 正式环境。

适用当前约定：

- 生产目录：`/srv/p-t/app`
- 测试目录：`/srv/p-t/green`
- 生产端口：`10001`
- 测试端口：`10002`
- 生产 compose project：`app`
- 测试 compose project：`app-green`

## 基本原则

- `10001` 对应正式业务入口。
- `10002` 对应 `green` 测试入口。
- 切换时只允许一套业务服务对外提供入口，避免同时误用。
- 监控容器可以单独保留，不影响业务切换。
- 不要执行 `docker compose down -v`，否则会删除持久化数据卷。

## 登录服务器

```bash
ssh root@103.147.13.98
```

## 切换到生产环境

场景：需要恢复正式业务，对外提供 `10001`。

### 1. 停止 green 业务服务

```bash
cd /srv/p-t/green
APP_ENV_FILE=.env.green docker compose -p app-green -f docker-compose.deploy.yml --env-file .env.green stop
```

### 2. 启动 production 业务服务

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -p app -f docker-compose.deploy.yml --env-file .env.production up -d
```

### 3. 验证状态

```bash
curl -f http://103.147.13.98:10001/api/health/live
curl -f http://103.147.13.98:10001/api/health/ready
curl -f http://103.147.13.98:10002/api/health/live
```

期望结果：

- `10001` 返回 `200`
- `10002` 不可达，或返回网关错误

### 4. 查看容器

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -p app -f docker-compose.deploy.yml --env-file .env.production ps
```

生产业务核心容器应至少包括：

- `app-app-server-1`
- `app-caddy-1`
- `app-matching-service-1`
- `app-postgres-1`
- `app-redis-1`

## 切换到 green 测试环境

场景：需要让测试环境接管对外访问，对外提供 `10002`。

### 1. 停止 production 业务服务

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -p app -f docker-compose.deploy.yml --env-file .env.production stop
```

说明：

- 这条命令会停止生产业务容器。
- 若你只想停业务、不停监控，可在执行后检查 `app-cadvisor-1`、`app-grafana-1`、`app-node-exporter-1`、`app-prometheus-1` 是否保留运行。

### 2. 启动 green 业务服务

```bash
cd /srv/p-t/green
APP_ENV_FILE=.env.green docker compose -p app-green -f docker-compose.deploy.yml --env-file .env.green up -d
```

如果要确保使用最新镜像和构建结果，可以改用：

```bash
cd /srv/p-t/green
APP_ENV_FILE=.env.green docker compose -p app-green -f docker-compose.deploy.yml --env-file .env.green up -d --build
```

### 3. 验证状态

```bash
curl -f http://103.147.13.98:10002/api/health/live
curl -f http://103.147.13.98:10002/api/health/ready
curl -f http://103.147.13.98:10001/api/health/live
```

期望结果：

- `10002` 返回 `200`
- `10001` 不可达，或返回网关错误

### 4. 查看容器

```bash
cd /srv/p-t/green
APP_ENV_FILE=.env.green docker compose -p app-green -f docker-compose.deploy.yml --env-file .env.green ps
```

测试业务核心容器应至少包括：

- `app-green-app-server-1`
- `app-green-caddy-1`
- `app-green-matching-service-1`
- `app-green-postgres-1`
- `app-green-redis-1`

## 推荐切换顺序

每次切换都建议按下面顺序做：

1. 先确认要切到哪一侧。
2. 先停当前在线的一侧。
3. 再启动目标一侧。
4. 立刻做 `health/live` 和 `health/ready` 检查。
5. 最后确认错误的一侧端口已经不可达。

## 当前实际对应关系

- 正式业务：`http://103.147.13.98:10001`
- 测试业务：`http://103.147.13.98:10002`

## 风险提醒

- 不要把 `green` 的数据库直接当成正式库。
- 不要在不确认端口状态的前提下让客户端切换环境。
- 不要执行 `docker compose down -v`。
- 若只是切换业务入口，不需要删除镜像，也不需要清空数据卷。
