# Hyper Terminal / BTC Paper Trading：Codex 总体需求与部署执行计划书

> 本文件供 Codex 直接阅读、拆分任务、修改代码、编写测试和部署使用。  
> 本版不是单纯追加需求，而是把旧的总体需求计划更新为：**先核验当前仓库已有码面痕迹，再补齐部署阻断项，再执行云服务器 + SD-WAN 部署**。  
> 重要限制：当前环境无法直接解压 RAR 源码逐行验证；所有“清单显示存在”的模块必须由 Codex 在仓库内运行测试后确认。

---

## 0. 总体执行原则

本项目的交付目标是稳定、可审计、可回滚、可长期运行的 BTC 5 分钟涨跌模拟盘。Codex 修改时必须优先保证：

```text
交易数据可信
权限边界可信
数据库升级可回滚
历史数据不丢失
PnL/手续费口径可解释
部署包不携带本地敏感数据
云服务器长期运行稳定
SD-WAN 访问路径清晰可维护
```

禁止事项：

```text
1. 不要删除 /api/logs/export；客户数据集导出必须另设 /api/datasets/export 或等价接口。
2. 不要删除 seniorTesterId；只能新增/优先使用 managerUserId 并兼容旧字段。
3. 不要删除 realizedPnl、unrealizedPnl、notionalSpent、averageEntry 等旧 PnL 字段。
4. 不要删除 CSV/TSV 批量创建；Excel 只能作为增强。
5. 不要删除 JSONL 审计能力；只能改为异步队列、轮转、结构化增强。
6. 不要让生产 app-server 静默 ALTER TABLE 或重建数据库。
7. 不要让 Electron 客户端执行数据库 migration。
8. 不要把真实 user_id、username、displayName 导出给客户数据集。
9. 不要只靠前端隐藏按钮实现权限；所有 API 必须后端鉴权。
10. 不要重写整个 App.tsx；先抽取、兼容、测试，再逐步清理。
11. 不要把 data/postgres、data/logs、.env、dist 打进生产源码包或 Docker 镜像。
12. 不要直接多开 app-server 副本；当前先做单实例强一致部署。
```

## 1. 当前项目距离部署的功能缺口

按上线功能组统计，当前还剩 **10 个部署前必须完成或验证的功能组**：

```text

G. JSONL 异步写入、轮转、shutdown flush。
H. health/ready/metrics/Prometheus/Grafana。
I. Electron 客户端生产打包与远端 URL。
J. 云服务器 + SD-WAN 完整部署、回滚、浸泡测试。
```

如果这些功能组都通过验收，项目可以进入正式部署。若只完成 A/B/C/I/J 的基础部分，只能进入 staging。

## 8. 阶段 5：PnL 与手续费口径标准化

### 8.1 目标

明确前端显示的盈亏是否包含买入手续费，避免重复扣费，并在导出中给出清晰字段。

### 8.2 当前清单显示

```text
apps/server/src/services/clob-fees.ts
apps/server/src/services/clob-execution.ts
apps/client/src/features/trade/pnl.ts
apps/client/src/features/trade/PositionPnlBreakdown.tsx
```

### 8.3 推荐口径

买入：

```text
grossEntryNotional = matchedNotional
entryFee = fee
costBasis = grossEntryNotional + entryFee
availableUsdc -= costBasis
position.notionalSpent += costBasis
position.averageEntry = position.notionalSpent / position.qty
```

卖出：

```text
grossExitProceeds = matchedNotional
exitFee = fee
netExitProceeds = grossExitProceeds - exitFee
releasedCostBasis = position.averageEntry * soldQty
realizedPnl = netExitProceeds - releasedCostBasis
availableUsdc += netExitProceeds
```

Redeem：

```text
redeemAmount = winningQty * 1.00
realizedPnl = redeemAmount - remainingCostBasis
availableUsdc += redeemAmount
```

浮动：

```text
markPnl = qty * markPrice - costBasis
executablePnl = qty * bestBid - estimatedExitFee - costBasis
```

### 8.4 字段要求

Order：

```text
feeModel
grossNotionalUsdc
feeUsdc
feeBps
netNotionalUsdc
estimatedFee
actualFee
feeBreakdown
feeCurrency
```

Position：

```text
entryFeeUsdc
exitFeeUsdc
totalFeeUsdc
costBasisUsdc
markValueUsdc
executableValueUsdc
markPnl
executablePnl
netRealizedPnl
netUnrealizedPnl
feeModel
```

旧字段必须保留并 fallback。

### 8.5 前端展示

持仓详情必须显示：

```text

成交均价
买入成交额
买入手续费
```

## 10. 阶段 7：C/S 长期部署稳定性、性能与容错

### 10.1 目标

支持数十人同时长期使用，后端和中间件全部在云服务器上，客户端通过 SD-WAN 访问。

### 10.2 必须实现或验证

```text
1. 交易关键写入事务化。
2. WS 不高频全量大包。
3. JSONL 不阻塞 event loop。
4. 上游 API 故障可降级。
5. PostgreSQL 可备份恢复。
6. health/live、health/ready、metrics 可用。
7. Docker 不暴露 PG/Redis/matching。
8. Electron 断线后可恢复。
9. 导出和日志查询不拖垮交易。
10. graceful shutdown 可 flush 日志并关闭连接。
```

### 10.3 SD-WAN 部署要求

详见：

```text
docs/PACKAGING_AND_SDWAN_DEPLOYMENT_WORKFLOW.md
```

核心原则：

```text
1. 客户端只通过 SD-WAN 私网地址访问服务。
2. 服务端业务入口绑定 SD-WAN IP 或由防火墙限制来源。
3. PostgreSQL、Redis、matching-service 只在 Docker 内网可访问。
4. 反代处理 HTTPS/WSS。
5. 客户端生产包写入远端 base URL。
```

### 10.4 验收

```bash
npx tsx scripts/deployment-readiness-check.ts
npx tsx scripts/fault-tolerance-check.ts
npx tsx scripts/metrics-check.ts
```

人工测试：

```text
1. 30 客户端在线 30 分钟。
2. 50 客户端连接/重连/收行情。
3. CLOB stale 后禁止新下单。
4. PG 暂时断开时严格模式禁止交易。
5. Redis 断开时按设计降级。
6. 导出 10 万行数据时 WS 心跳不断。
7. 备份恢复到新库成功。
```
