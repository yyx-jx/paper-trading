7. Server and Connection Issues Mentioned in Reports

- Production version mentioned in the order-lag fix report
  - p-t-app-server:v072fix2
  - Git branch release/1.0.1
  Sources:
  - 下单卡顿修复报告.md

- Production crash / gateway errors mentioned in the report
  - app-server crashed and restarted 3 times when real testers came online after deployment
  - Intermittent 502 errors for testers
  Sources:
  - 下单卡顿修复报告.md

- Connector issues confirmed in the report
  - Existing bug in 0.7.2: CoinbaseConnector.scheduleReconnect calls close() on a socket that is still in CONNECTING state after removeAllListeners()
  - The ws layer emitted an error with no listener, causing an uncaught exception and process crash
  - Similar fixes were also added to binance.ts; no similar issue was found after checking Polymarket
  Sources:
  - 下单卡顿修复报告.md

- Mitigation measures mentioned in the report
  - First set COINBASE_ENABLED=false and restart
  - Restore COINBASE_ENABLED=true after the fix is completed
  Sources:
  - 下单卡顿修复报告.md

- PostgreSQL connection risks mentioned in the report
  - Periodic transient disconnects occurred between app-server and PostgreSQL
  - Short-lived 503 responses may occur in strict mode
  - Log keywords: PostgreSQL reconnecting / Position sell blocked
  - Recommended checks: PG idle timeout, keepalive, minimum keepalive connections
  - Data in the report: idle timeout is currently 60s, about 17,000 sessions accumulated over 23h, about 12 connection rebuilds per minute
  Sources:
  - 下单卡顿修复报告.md

- Verification status of the new production server
  - docs/Coinbase数据源卡死根因与修复记录.md states that after the fix was deployed to 103.179.242.161, app-server, matching-service, caddy, postgres, and redis were all healthy
  Sources:
  - docs/Coinbase数据源卡死根因与修复记录.md
