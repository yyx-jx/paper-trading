# P_T 完整打包流程与云服务器 SD-WAN 部署工作流

---

## 1. 目标部署形态

```text
Electron Client(s)
  ↓ HTTPS/WSS over SD-WAN
SD-WAN private IP / private DNS
  ↓
Cloud Server Firewall
  ↓
Caddy or Nginx reverse proxy
  ↓ internal Docker network
Fastify app-server
  ↓
PostgreSQL
Redis
optional matching-service
rotated JSONL logs
Prometheus/Grafana
Backups
```

### 1.1 推荐端口策略

| 服务 | 容器端口 | 宿主机暴露 | 说明 |
|---|---:|---:|---|
| Caddy/Nginx | 80/10001 | 仅 SD-WAN IP 或受防火墙限制 | 客户端唯一入口，处理 HTTPS/WSS。 |
| app-server | 8787 | 不暴露公网 | 只允许反代访问。 |
| matching-service | 8788 | 不暴露公网 | 可选，只允许 app-server 内网访问。 |
| PostgreSQL | 5432 | 不暴露公网 | 只允许 Docker 内网访问。 |
| Redis | 6379 | 不暴露公网 | 只允许 Docker 内网访问。 |
| Prometheus/Grafana | 9090/3000 | 不暴露公网或仅管理端 SD-WAN | 运维访问。 |

### 7.2 系统用户

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin p-t || true
sudo mkdir -p /srv/p-t/{app,data/postgres,data/redis,data/logs,data/backups,releases,rollback}
sudo chown -R p-t:p-t /srv/p-t
```

### 7.3 防火墙原则

```text
1. 允许 SSH 管理来源。
2. 允许 SD-WAN 接口/网段访问 443。
3. 不允许公网访问 8787、8788、5432、6379。
4. Prometheus/Grafana 仅允许运维 SD-WAN 网段访问。
```

如果业务入口只走 SD-WAN，Caddy/Nginx 可以绑定 SD-WAN IP：

```text
https://<sdwan-ip>:443
```

或通过防火墙只允许 SD-WAN 网段访问 443。

## 8. SD-WAN 配置流程

> 本文保持供应商无关。无论使用哪种 SD-WAN/Overlay 工具，目标都是：客户端与云服务器获得同一私网内可路由地址，并通过该私网地址访问 HTTPS/WSS。

### 8.1 服务器侧

```text
1. 云服务器加入 SD-WAN 网络。
2. 记录服务器 SD-WAN IP，例如 100.x.x.x / 10.x.x.x。
3. 配置私网 DNS 名称，例如 papertrade.sdw。
4. 防火墙允许 SD-WAN 网段访问 443。
5. Caddy/Nginx 监听 SD-WAN IP 或 0.0.0.0:443 但由防火墙限制来源。
```

### 8.2 客户端侧

```text
1. 每台运行 Electron 客户端的电脑加入同一 SD-WAN 网络。
2. 验证能 ping 或 curl 服务器 SD-WAN IP。
3. 验证能访问 https://papertrade.sdw/api/health/live。
4. Electron 客户端使用 https://papertrade.sdw 和 wss://papertrade.sdw。
```

### 8.3 证书策略

可选方案：

```text
方案 A：使用真实域名 + 私网 DNS 指向 SD-WAN IP + 公共 TLS 证书。
方案 B：使用内部 CA 证书，安装到客户端信任根。
方案 C：测试环境临时使用自签证书，但正式环境不建议。
```

要求：

```text
1. Electron 客户端不能长期关闭证书校验。
2. 证书域名必须匹配 VITE_API_BASE_URL。
3. WSS 与 HTTPS 使用同一可信证书。
```

## 10. docker-compose.deploy.yml 目标结构

Codex 应使 compose 满足以下逻辑：

```yaml
services:
  caddy:
    image: caddy:2
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - ./deploy/Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - app-server

  app-server:
    build:
      context: .
      dockerfile: Dockerfile.server
    env_file:
      - .env.production
    volumes:
      - logs:/app/data/logs
      - backups:/app/data/backups
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    expose:
      - "8787"

  matching-service:
    build:
      context: .
      dockerfile: Dockerfile.server
    command: ["node", "dist/matching-index.js"]
    env_file:
      - .env.production
    expose:
      - "8788"

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_DB: paper_trading
      POSTGRES_USER: paper_app
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?required}
    volumes:
      - pgdata:/var/lib/postgresql/data
    expose:
      - "5432"

  redis:
    image: redis:8-alpine
    volumes:
      - redisdata:/data
    expose:
      - "6379"

volumes:
  pgdata:
  redisdata:
  logs:
  backups:
  caddy_data:
  caddy_config:
```

注意：具体版本和命令以当前项目实际 Dockerfile/package scripts 为准；Codex 必须运行 `docker compose config` 验证。

## 11. Caddyfile 目标配置

```caddyfile
papertrade.sdw {
  encode gzip zstd

  reverse_proxy app-server:8787 {
    header_up X-Forwarded-Proto {scheme}
    header_up X-Forwarded-Host {host}
    header_up X-Real-IP {remote_host}
  }
}
```

如果使用内部证书：

```caddyfile
papertrade.sdw {
  tls internal
  reverse_proxy app-server:8787
}
```

如果使用 Nginx，必须配置 WebSocket upgrade：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

## 12. 首次部署流程

### 12.1 上传 release

```bash
rsync -av release/P_T_<version>_<date>/server/ user@cloud:/srv/p-t/app/
```

### 12.2 配置 env

```bash
cd /srv/p-t/app
cp .env.production.example .env.production
nano .env.production
```

必须替换：

```text
DATABASE_URL
POSTGRES_PASSWORD
JWT_SECRET
EXPORT_ANONYMIZATION_SECRET
PUBLIC_BASE_URL
CORS_ORIGIN
```

### 12.3 启动中间件

```bash
docker compose -f docker-compose.deploy.yml --env-file .env.production up -d postgres redis
```

### 12.4 执行迁移

```bash
docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server npm run db:migrate
```

### 12.5 创建第一个 Admin

推荐通过脚本：

```bash
docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server \
  npx tsx scripts/create-admin.ts --username admin --display-name Admin
```

如果当前仓库没有 `scripts/create-admin.ts`，Codex 必须新增；不要依赖默认账号。

### 12.6 启动全量服务

```bash
docker compose -f docker-compose.deploy.yml --env-file .env.production up -d
```

### 12.7 健康检查

```bash
curl -k https://papertrade.sdw/api/health/live
curl -k https://papertrade.sdw/api/health/ready
curl -k https://papertrade.sdw/metrics | head
```

### 12.8 部署检查脚本

```bash
docker compose -f docker-compose.deploy.yml --env-file .env.production exec app-server \
  npx tsx scripts/deployment-readiness-check.ts
```

## 14. 日常启动、停止、升级

### 14.1 查看状态

```bash
cd /srv/p-t/app
docker compose -f docker-compose.deploy.yml ps
docker compose -f docker-compose.deploy.yml logs -f app-server
```

### 14.2 停止

```bash
docker compose -f docker-compose.deploy.yml stop app-server matching-service
```

### 14.3 完整停止

```bash
docker compose -f docker-compose.deploy.yml down
```

不要随意执行带 `-v` 的 down，除非明确要删除 volumes。

### 14.4 升级流程

```text
1. 通知维护窗口。
2. 关闭新订单入口或停止 app-server。
3. 执行 db backup。
4. 上传新 release。
5. 执行 db migrate。
6. 启动新 app-server。
7. health/ready/metrics 验证。
8. 登录、下单、撤单、导出 smoke test。
9. 恢复访问。
```

命令示例：

```bash
cd /srv/p-t/app
npm run db:backup || docker compose run --rm app-server npm run db:backup
docker compose stop app-server
rsync -av /tmp/new-release/server/ /srv/p-t/app/
docker compose run --rm app-server npm run db:migrate
docker compose up -d
```

## 16. 回滚流程

### 16.1 代码回滚

```bash
cd /srv/p-t/app
docker compose stop app-server
rsync -av /srv/p-t/rollback/<previous-release>/server/ /srv/p-t/app/
docker compose up -d app-server
```

### 16.2 数据库回滚

如果 migration 已改变 schema 且无法兼容旧代码，只能使用备份恢复：

```bash
export BACKUP_FILE=/srv/p-t/data/backups/<before-upgrade>.dump
docker compose run --rm app-server npm run db:restore
```

注意：数据库恢复会覆盖升级后产生的数据。正式环境应先评估数据影响。

## 18. 常见故障处理

### 18.1 ready 失败

排查：

```bash
docker compose logs app-server
docker compose exec postgres pg_isready
docker compose exec redis redis-cli ping
```

常见原因：

```text
DATABASE_URL 错误
schema 未迁移
JWT_SECRET/EXPORT secret 缺失
日志目录不可写
Redis 未启动
```

### 18.2 客户端连不上

排查：

```text
1. 客户端是否加入 SD-WAN。
2. papertrade.sdw 是否解析到服务器 SD-WAN IP。
3. 证书域名是否匹配。
4. CORS_ORIGIN 是否等于客户端 origin。
5. Caddy 是否能反代到 app-server。
6. app-server 是否 ready。
```

### 18.3 WS 频繁断开

排查：

```text
1. 证书是否可信。
2. Caddy/Nginx 是否支持 WebSocket upgrade。
3. ticket 是否过期或重放。
4. MAX_WS_CONNECTIONS_PER_USER 是否过低。
5. 慢客户端 bufferedAmount 是否过高。
```

### 18.4 下单失败

排查：

```text
1. CLOB 盘口是否 stale。
2. PostgreSQL 是否可写。
3. SERVER_STRICT_PERSISTENCE 是否阻断了弱持久化。
4. 用户余额/权限/permissionLevel 是否允许。
5. 当前 round 是否在 freeze window。
```

## 19. 给 Codex 的部署执行摘要

```text
1. 清理 release 包，排除 data/.env/dist。
2. 设置 .env.production 和强 secret。
3. 云服务器加入 SD-WAN。
4. Caddy 绑定 SD-WAN 域名/IP，反代 app-server。
5. 启动 PG/Redis。
6. 执行 db:migrate。
7. 创建 Admin。
8. 启动 app-server/matching/monitoring。
9. health/ready/metrics 验证。
10. 打包 Electron 客户端，写入 https/wss SD-WAN URL。
11. 做 smoke、负载、故障、备份恢复测试。
12. staging 通过后正式开放。
```
