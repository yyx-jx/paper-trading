# 打包发布工作流

## 1. 本地检查

每次代码修改后，先执行：

```bash
npm ci
npm run typecheck
npm run build
npm run test:config
npm run test:permissions
npm run test:deployment
npm run test:deployment-readiness
npm run test:migration-safety
npm run test:order-transactions
npm run test:redeem-idempotency
npm run test:electron-config
```

任何失败都必须先修复，不进入打包和部署。

## 2. 服务端 release 打包

```bash
npm run package:release
```

release 输出在：

```text
release/P_T_<version>_<timestamp>/
```

打包脚本会生成：

```text
server/
checksums.sha256
```

release 包不得包含：

```text
.env
data/
backups/
node_modules/
dist/
release/
```

## 3. Windows 客户端打包

当前临时 HTTP 生产客户端：

```bash
ALLOW_INSECURE_PROD_HTTP=true VITE_API_BASE_URL=http://103.147.13.98:10001 npm run package:win:prod
```

输出：

```text
deploy/windows-production/BTC Paper Trading Setup.exe
```

生产客户端会把 `VITE_API_BASE_URL` 写入安装包元数据 `productionApiBaseUrl`。Electron 启动时会自动为该地址配置 `proxy-bypass-list`，避免用户本机系统代理导致 `103.147.13.98:10001` 请求超时并显示“后端离线”。

后续切换 HTTPS 后改为：

```bash
VITE_API_BASE_URL=https://<正式域名> npm run package:win:prod
```

## 4. 上传 release

```bash
ssh -p 22 root@103.147.13.98 "mkdir -p /srv/p-t/{app,releases,rollback,data/backups}"
scp -P 22 -r release/<release>/server root@103.147.13.98:/srv/p-t/releases/<release>/
scp -P 22 release/<release>/checksums.sha256 root@103.147.13.98:/srv/p-t/releases/<release>/
```

上传后在远程校验：

```bash
cd /srv/p-t/releases/<release>
sha256sum -c checksums.sha256
```

## 5. 发布到 app 目录

发布前保留回滚副本：

```bash
ts=$(date +%Y%m%d_%H%M%S)
mkdir -p /srv/p-t/rollback/$ts
cp -a /srv/p-t/app/. /srv/p-t/rollback/$ts/
rm -rf /srv/p-t/app
mkdir -p /srv/p-t/app
cp -a /srv/p-t/releases/<release>/server/. /srv/p-t/app/
```

不要覆盖或提交真实 `.env.production` 到 Git。

## 6. 数据库备份和迁移

升级前备份：

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server npm run db:backup
```

迁移：

```bash
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server npm run db:migrate
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server npm run db:status
```

数据库变更规则：

```text
允许新增表、字段、索引、兼容式回填。
禁止 DROP、TRUNCATE、无 WHERE DELETE、重建 schema。
旧字段至少保留一个发布周期。
```

## 7. 启动服务

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production up -d --build
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production ps
```

如果远程 Docker Hub 不可用，不要在生产机反复等待构建。当前已保存可恢复的生产镜像离线包：

```text
/srv/p-t/releases/image-backups/p-t-fixed-images_20260509_003005.tar.gz
/srv/p-t/releases/image-backups/p-t-fixed-images_20260509_003005.tar.gz.sha256
```

离线恢复：

```bash
cd /srv/p-t/releases/image-backups
sha256sum -c p-t-fixed-images_20260509_003005.tar.gz.sha256
gunzip -c p-t-fixed-images_20260509_003005.tar.gz | docker load
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production up -d --no-build
```

2026-05-09 检查到远程 Docker 访问 `registry-1.docker.io` 会拿到 `unifi.local/localhost` 证书，标准构建会失败。恢复标准构建前，需要先修复服务器 DNS、网关、代理或 Docker registry mirror。

首次部署创建 Admin：

```bash
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production run --rm app-server npx tsx scripts/create-admin.ts --username admin --display-name Admin
```

## 8. 验收

本机和外部都要验证：

```bash
curl -f http://127.0.0.1:10001/api/health/live
curl -f http://127.0.0.1:10001/api/health/ready
curl -f http://103.147.13.98:10001/api/health/live
curl -f http://103.147.13.98:10001/api/health/ready
```

客户端 smoke：

```text
登录
行情 WS
用户 WS
下单
撤单
卖出/平仓
日志查询
```

连接压力测试：

```bash
LOAD_TEST_BASE_URL=http://103.147.13.98:10001 \
LOAD_TEST_ADMIN_USERNAME=admin \
LOAD_TEST_ADMIN_PASSWORD=<从 /srv/p-t/deployment-secrets-current.txt 读取> \
LOAD_TEST_PREFIX=load_$(date +%Y%m%d_%H%M%S) \
npm run test:production-client-load
```

通过标准：

```text
30 个客户端在线 30 分钟，最终 30/30 在线，60/60 WS open，health 全程 ok。
50 个客户端 5 轮连接/重连，最终 50/50 在线，100/100 WS open，health 全程 ok。
异常断开为 0，最长连接缺口为 0ms。
测试账号必须全部禁用。
```

## 9. 回滚

代码回滚：

```bash
cd /srv/p-t/app
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production stop app-server matching-service caddy
cp -a /srv/p-t/rollback/<timestamp>/. /srv/p-t/app/
APP_ENV_FILE=.env.production docker compose -f docker-compose.deploy.yml --env-file .env.production up -d --build
```

数据库回滚只有 schema 不兼容时才执行，会覆盖备份后产生的数据。

禁止：

```bash
docker compose down -v
```
